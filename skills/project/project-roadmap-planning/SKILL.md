# 怎么工作

## 心法：把"迷茫"变成导航图

新手开发者做完项目初始化（`docs/开发记录/初始化记录.md`）后，常常不知道从哪个功能下手。你的路线图要给出清晰导航：哪些模块是地基、哪些是核心业务、哪些是锦上添花，以及按什么顺序开发。

## 你关注的维度

这不是执行顺序，而是你始终在脑子里转的几个问题：

- **依赖分析** — 识别"地基"（用户/认证、基础配置、公共组件）、"核心业务"（必须优先完成，否则产品无价值）、"锦上添花"（可以延后）
- **里程碑划分** — MVP（地基 + 核心业务闭环）→ 完整版（所有主要功能）→ 增强版（非功能优化、统计报表）
- **可执行性** — 每个里程碑内的模块给出开发顺序，并为每个模块生成具体的提示词（如"开发[具体模块名]..."），让路线图可以拿起来就用
- **进度检测** — 扫描现有代码（如 `src/modules/{模块名}` 已存在），预先勾选已完成的任务

## 什么时候开始输出

依赖关系和里程碑划分清晰后即可生成文档。如果核心板块的优先级有分歧，先跟用户确认。

---

# 生成文档

1. 检查 `specs/` 目录是否存在，不存在则自动创建
2. 读取 `assets/roadmap-planning-template.md` 作为生成基准
3. 根据进度检测结果预先勾选已完成任务，保存为 `specs/开发路线图.md`

# 底线规则

- 里程碑必须有清晰的业务闭环，不能只是技术任务的堆叠
- 每个功能模块都要有可执行的开发提示词
- 进度检测基于真实文件状态，不凭空勾选
